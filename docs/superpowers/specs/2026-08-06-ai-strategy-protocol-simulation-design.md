# AI 策略、API 协议与整局模拟设计

## 目标

在不改变服务端权威结算的前提下，让房主可选择保守、均衡或激进 AI，为未来外部 AI 服务提供严格的 `v1` 协议与脱敏调用审计，并用固定随机种子的完整对局模拟防止 AI 卡回合或破坏资产数据。

## 决策

- 难度使用房间级 `aiDifficulty`，所有补位 AI 共用，避免大厅为每个 AI 增加一套配置。
- `conservative` 保留更多现金、不主动使用攻击卡，股票仓位较小；`balanced` 保留现有行为；`aggressive` 降低买地和升级现金储备，并扩大准确情报仓位。
- API 只接受 `qiqu-ai/1` 信封：请求包含 `version`、`requestId` 和玩家视角上下文；响应必须回传相同版本与 `requestId`。
- 审计仅保存请求 ID、房间、AI 玩家、提供器、命令类型、耗时和结果，不保存 API Key、完整 GameState 或请求正文；内存环形队列默认最多 500 条。
- 本地硬编码 AI 仍是默认与最终兜底；API 协议错误、超时、身份不符或动作被拒绝都不能跳过服务端校验。

## 整局模拟

模拟直接调用服务端 `getAiTurnCommand` 与 `executeAiTurnCommand`，不伪造 Socket 结果。每步检查现金、存款、负债、地产归属、股票持仓和当前回合游标，并要求不同种子的 4 人与 8 人短局在步数上限内结束。

## 验收

- 房主可在大厅修改三档 AI 难度，非房主和开局后不能修改。
- 三档策略在同一买地、攻击卡和准确股票情报场景中产生可验证的不同决策。
- API 版本、请求 ID 或命令非法时回落本地 AI，审计中可见原因但没有敏感数据。
- 完整局模拟不卡住，不产生 `NaN`/无限资产、负持仓或地产所有权不一致。
